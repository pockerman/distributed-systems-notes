# Lesson 7: TLS 101

## Overview

The previous lesson, [Lesson 6: TCP](2026-03-17-part-4-TCP_101.md), discussed TCP
and how it provides reliable communication between processes. However, TCP provides no security. In this lesson
we discuss [Transport Layer Security](https://en.wikipedia.org/wiki/Transport_Layer_Security), or TLS.
In a nutshell, TLS runs on top of TCP and provides encryption, authentication, and integrity [1].

## TLS 101

Although TCP offers reliability, anyone on the network path can read or modify the data it carries. To secure communication
over TCP we can use TLS, which provides:

- Encryption
- Authentication
- Integrity

Let's briefly discuss each of these.

### Encryption

Encryption guarantees that the data transmitted between a client and a server can only be read by the two communicating
processes. First, the two processes have to agree on a shared encryption secret.
This is done during the TLS handshake using asymmetric cryptography, e.g. a Diffie–Hellman key exchange [1, 2]. Asymmetric cryptography is slow, but it is only used to establish the shared key. After that,
symmetric encryption, which is fast and cheap, is used for the rest of the connection. It is good practice to use TLS for all communication, even traffic that does not
go over the public internet.

### Authentication

Authentication allows the client to verify that the server is who it claims to be.
TLS implements authentication using digital signatures based on asymmetric cryptography [1].
The server holds a private key and presents a certificate containing the matching public key. During the handshake, the server proves it owns the private key by signing data with it.
For the client to trust that the public key really belongs to the server, the certificate is signed by a certificate authority (CA) that the client trusts; the client verifies the chain of certificates up to a trusted root CA.

### Integrity

Although encryption keeps the data secret, an attacker in the middle could still flip bits in the encrypted messages;
this is called tampering [1]. To protect against tampering, TLS verifies the integrity of each message with a message authentication code (MAC). Modern TLS uses authenticated encryption (AEAD) ciphers, which encrypt the data and protect its integrity in one step.

## Summary

::: {.callout-note title="Summary"}
TLS (Transport Layer Security) is a protocol that runs on top of TCP and adds encryption, authentication, and integrity to otherwise insecure network communication. While TCP ensures reliable data transfer, it does not protect data from being read or altered. TLS first uses asymmetric cryptography to securely establish a shared secret key, then switches to fast symmetric encryption for the rest of the connection. It authenticates the server through certificates signed by trusted certificate authorities, so clients know they are talking to the legitimate server. Finally, TLS protects data integrity with message authentication codes, so any tampering in transit is detected.
:::
